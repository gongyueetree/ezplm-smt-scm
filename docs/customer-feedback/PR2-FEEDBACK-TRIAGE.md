# PR2 版本客户试用反馈 —— 分诊表

来源:`docs/AI PR2版本适用反馈.pdf`(客户试用后逐页意见,4 页)
建立时间:2026-08-10

## 怎么读这张表

反馈里混着三类完全不同的东西,**不能一锅端**:

| 分类 | 含义 | 处理方式 |
|---|---|---|
| **缺陷** | 现有功能行为错误,能在代码里找到证据 | 直接修,按小 PR |
| **小改** | 功能在,但形态/入口不合用 | 排批次修 |
| **提问** | 客户在问"这是什么/为什么这样" | 回答,可能引出需求 |
| **新功能** | 现在没有,要新建模块或接外部系统 | **进「待商务确认」池**,不默默吸入(CLAUDE.md 硬性约束 8) |
| **超范围** | CLAUDE.md 明确本阶段不做 | 记 backlog,明确告知 |

> 纪律:范围变更一律进"待商务确认"池。下面标 **新功能 / 超范围** 的条目,
> 在商务确认工作量与排期之前不开工。

## 一、已确认的**缺陷**(有代码证据)

| 编号 | 反馈原文 | 证据 | 状态 |
|---|---|---|---|
| **D-1** | PM-4「导入 BOM 的时间和实际导入时间不匹配」 | 全仓 **28 处**用 `toISOString()` 直接渲染时间。`toISOString()` 是 **UTC**,客户在 UTC+8 —— 每个创建/导入/更新时间都**早 8 小时** | ✅ 已修(本批) |
| **D-2** | 采购-6C「阶梯价格以报价数量分行显示,不用分号区别」 | `app/(app)/procurement/suppliers/forms.tsx` 阶梯价是单个文本框 `"1:0.12, 1000:0.10"`,靠逗号冒号解析,**填错的档被 filter 静默丢掉**;且表单预填假价格,不改就当真数据存入 | ✅ 已修(本批) |
| **D-3** | 工程-3「BOM 对比界面没有输入口」 | `app/(app)/bom/compare/page.tsx` 只能靠 URL 参数或从台账跳入,页内无版本选择控件 | 待复核 |
| **D-4** | 工程-1「上传 BOM 时显示未能识别必需列…是否是格式不兼容?」 | 提示文案让客户误以为是格式错误,实际是要人工指定列映射 | 待修(措辞) |
