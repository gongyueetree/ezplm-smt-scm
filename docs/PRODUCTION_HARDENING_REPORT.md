# Production Hardening Report

> 日期:2026-08-01 · 范围:PR-D ~ PR-H(GitHub PR #5–#9)
> 约束:不新增业务模块、不重构 UI、不破坏已有数据。全部修改为**加固**,非重写。

## 零、结论摘要

五个 PR 共修补 **21 项**生产级问题,其中 **3 项是会造成实际业务后果的严重缺陷**:

| 严重度 | 问题 | 后果 |
|---|---|---|
| 🔴 **P0** | OPO 未做供应商行级过滤 | **数据泄露**:供应商可见所有同行的料号、数量、单价、交期 |
| 🔴 **P0** | 同步作业状态写死 `SUCCEEDED` | 部分失败被报成功;重跑会把已成功的行**重复写入 ERP** |
| 🔴 **P0** | 影响面把 PCS 与 Reel 直接相加 | 无意义的数字被用于**召回决策** |

另有 **4 项缺陷是被测试抓出来的**,而非事先想到的 —— 详见 §四。

累计:新增 **9 个纯函数领域模块**、**1189 → 1199 条单测**、**131 → 150 条 E2E**、**3 个迁移(全部纯新增)**。

## 一、逐 PR 修补清单

### PR-D · ERP 同步可靠性(#5)

| # | 问题 | 为什么这样设计 |
|---|---|---|
| 1 | **作业状态写死 `SUCCEEDED`** | 改为由行级结果派生。`PARTIAL_SUCCESS` 设为**独立终态**而非 FAILED 变体 —— ERP 同步最常见的情形就是"200 行里 3 行失败",把它归入任一极端都会误导操作 |
| 2 | 失败即终态,无重试 | 指数退避(30s→2m→8m,上限 1h)+ **只重试失败行** + 断点续跑 |
| 3 | 无限重试风险 | 次数耗尽转 `DEAD_LETTER` 并**停止自动重试**。依据是真实教训:本项目 DigiKey 日配额 1000 次曾被 E2E 打光。外部故障时持续重试等于加剧对方压力并耗尽自己配额 |
| 4 | 游标只有一个 | 拆成「尝试水位」与「成功水位」,**只有整批成功才推进** —— 用失败游标恢复会跳过数据 |
| 5 | ERP 回执压成一个"成功" | 五态分开:已生成模板 / 已发送 / ERP 已接收 / ERP 已建单 / ERP 拒绝。`isPostedInErp()` **只认 ERP_POSTED**,接收只代表报文收到了 |
| 6 | 只有最后一次测试结果 | 健康度按**趋势**判定(连续失败、多久没成功、Token 剩余),并附**人可读依据** |
| 7 | 从未成功的连接显示绿灯 | 新增 `UNVERIFIED` 状态 —— 刚填完没测过 ≠ 健康 |
| 8 | 密钥轮换作废所有凭据 | 加 `keyVersion`,现有 AES 实现**不动** |

### PR-E · Trace Graph 增强(#6)

| # | 问题 | 为什么这样设计 |
|---|---|---|
| 9 | **PCS 与 Reel 直接相加** | 按 `baseUom` 分组合计,单位不一致标 `mixedUom` 不相加;缺系数的边单独计数;**系数为 0 视为无效**(否则数量凭空消失) |
| 10 | 影响面结论没有可信度 | 按**链路分段**算覆盖率 → HIGH/MEDIUM/LOW,**附人可读依据** |
| 11 | 加权平均掩盖单段塌陷 | **单段覆盖率单独约束**:三段满分 + 一段 60% 平均仍 90 分,但那 40% 下游看不见,给 HIGH 是危险的 |
| 12 | 低置信度可能被当"无影响" | `conclusionCaveat` 在 LOW 时**明写"不得据此判定无影响"** |
| 13 | 分析结果不留痕 | `TraceAnalysisRun` 固化快照 + 数据缺口 + `analysisAsOf` —— 调查持续数周,不存快照事后说不清"当时按什么数据下的隔离决定" |
| 14 | 拆分/合并让链路断掉 | `LotSplitMerge` **同时补图边**与时间线事件 —— 客户投诉的往往正是拆出去的那一小批 |
| 15 | 生产替代料无处记录 | `TraceSubstitution`,**不改 BOM**(写回会让历史 BOM 失真);**无批准人显式警示** |
| 16 | 缺外部来源字段 | 六张表统一加 `sourceSystem`/`externalId` 等,为真实 ERP 映射备好 |
| 17 | **BOM 版本下拉静默截断** | 原 `take: 30`,超出的版本不可选**且无提示**(实测 37 个版本时 07-29 那批已选不到)。改 200 并**明确告知** |

### PR-F · 物料生命周期(#7)

| # | 问题 | 为什么这样设计 |
|---|---|---|
| 18 | **草稿物料可进正式 BOM** | 只有 `ACTIVE` 可用,且**每种被拒状态给不同说明**(催审核 / 换替代料 / 恢复启用)—— 一句"状态不允许"让人不知下一步做什么 |
| 19 | 缺 `OBSOLETE` | `DISABLED`(可恢复)与 `OBSOLETE`(永久)语义不同;**仍被 BOM 引用的不得淘汰** |
| 20 | 编码规则写在 placeholder 里 | `PartCodeRule` 可配 + **预览下三个号**;关闭人工指定后**拒绝而不是悄悄替换** |
| 21 | 合规压成两个布尔值 | 拆成**声明** + **多对多支撑文档**。三条口径:UNKNOWN ≠ NON_COMPLIANT;**过期降级为 UNKNOWN 而非不合规**;**声称符合却无文档 → 不作数** |

### PR-G · 统一数据范围(#8)

| # | 问题 | 为什么这样设计 |
|---|---|---|
| 🔴 | **OPO 无供应商行级过滤** | 供应商可见全部同行数据。演示库 78 行恰好同属一家,故一直未暴露 —— **接入第二家即泄露** |
| — | 导出接口同样未过滤 | 页面挡住但导出是绕过口,一并修 |
| — | 范围逻辑散落 25+12 处 | 抽成统一策略。**默认最窄**:未知一律 NONE 不 fallback 到 ALL ——「放开的默认值出错时无声无息,收紧的出错时会被立刻发现」 |
| — | 归属缺失时的行为 | **看不到而不是看全部**,并提示"请设置归属" |
| — | 受限视图措辞 | **不能说"没有数据"**,要说「看不到的部分不代表不存在」 |

### PR-H · 运维可观测性(#9)

| # | 问题 | 为什么这样设计 |
|---|---|---|
| — | 只有"最近一次结果" | 汇总成功率 / 部分成功率 / 平均与 P95 耗时 / 平均重试次数 / 行级失败率 / 队列积压 |
| — | **无样本时报 0** | 一律返回 `null`,展示为「无样本」—— 0% 成功率与"这周没跑过"是两回事 |
| — | 部分成功被并入成功 | 单独统计 |

### 数据库

**只新增,无修改无删除**。唯一签名变更是内部函数 `getOpoDashboard(tenantId, now) → (session, now)`,唯一调用方已同步。

### UI

仅两处**增加说明**,无页面重构:采购比价页的截断提示、OPO 页的受限视图提示。

### 回滚

每个 PR 均可独立回滚:迁移用 `prisma migrate resolve --rolled-back`;新列可空或有默认值,旧代码读不到新列也能正常工作。
唯一需注意:回滚 PR-G 会**恢复 OPO 数据泄露**,不建议。

## 四、被测试抓出来的缺陷(而非事先想到的)

这四项值得单独记录 —— 它们说明**先写测试断言业务口径**确实能发现设计缺陷:

1. **覆盖率把单段塌陷判成 HIGH**(PR-E 单测)
   三段满分 + 一段 60% → 平均 90 分 → 判"数据完整,可直接用于决策"。
   实际那 40% 缺失意味着该段下游完全不可见。**改的是代码,不是测试。**

2. **P95 低估尾部**(PR-H 单测)
   `floor((n-1)*p)` 在小样本时把 `[1s, 9s]` 的 P95 算成 1s。
   P95 的用途正是发现慢作业,**低估是危险方向**。改为最近秩法。

3. **`?days=abc` 产生 Invalid Date**(PR-H E2E)
   NaN 经 `Math.min/max` 传播后进入查询条件。

4. **BOM 版本下拉静默截断**(PR-E E2E 失败时顺藤查出)
   不是计划内的修补项,是排查测试失败时发现的真实生产缺陷。

另有两次是**测试自身**的问题,同样如实记录:
- 权限用例并行时互相打架(一条撤销、另一条同时授予)→ 改为串行;
- 建料接口返回 `partId` 而非 `id`,误用 `.id` 会让 GET 查 `undefined` 返回空集 —— 用例**因为错误的原因通过**。这类"假绿"比失败更危险。

## 五、仍需真实 ERP / MES 联调才能完成上线的部分

以下能力**接口与数据结构已就位,但没有真实数据流**。不得在验收时按"已完成"计:

| 项 | 当前状态 | 需要什么 |
|---|---|---|
| ERP 回执字段(`erpDocumentId`/`postedAt`) | 结构已备,**无写入方** | 金蝶/用友账套开通 + Adapter 联调。当前 Excel 通道只走 `TEMPLATE_GENERATED`,**不会伪造 `ERP_POSTED`** |
| `tokenExpiresAt` | 字段已备,仅金蝶骨架预留回填点 | Provider 鉴权时返回过期时间 |
| 追溯外部来源字段 | 结构已备,**无写入方** | ERP 同步落库通道接通后填充 |
| 单位换算系数 | 靠导入提供 | 真实场景应由 ERP 物料主数据带出 |
| 增量游标 | 逻辑已备 | 需真实 ERP 的增量接口确认游标语义 |
| SN 级追溯 | **不在本期范围** | MES / SN 数据源 |
